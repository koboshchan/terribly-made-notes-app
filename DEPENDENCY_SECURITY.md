Dependency review for Notes PR4

The original audited head e241fe05ed4f2e59d35b9574ab93d4fe20e359f4 and combined PR5 402cf9d8fb72acd6a41942c204e48fdba15ce949 share lock SHA256 1807476d2d18d3654a309f37085984a70ef7043df4014d0d46f85dd7bdd710f8. The manifest next range ^16.1.4 actually resolved to installed Next 16.3.6. This patch keeps package.json unchanged and updates only eleven lock records, Next, @next/env and eight SWC packages from 16.3.6 to 16.3.8, and source-map-js from 1.2.1 to 1.2.2. npm publication, tarball integrity and official fixed versions were verified. No broad update or npm audit fix was used.

Next 16.3.8 fixes GHSA-cjq9-62q9-8jv4 (high SSRF, >=16.0.0 <16.3.8), GHSA-3w37-wq28-93x7 (moderate Draft Mode cache leak, >=16.3.0 <16.3.8), GHSA-4jqv-mc3x-m676 (moderate Pages Router SSG/ISR cache poisoning, >=16.0.0 <16.3.8), GHSA-39w2-rjm5-chcv (low next dev MCP disclosure, >=16.0.0 <16.3.8), GHSA-f87g-xv8r-7p7x (moderate webpack metadata-image dynamicParams bypass, >=16.0.0 <16.3.8), and GHSA-mcj8-r9mp-w47p (moderate root-catch-all SSG/ISR cache poisoning, >=16.0.0 <16.3.8). This app has no remotePatterns, Cache Components/useCache/Draft Mode, Pages Router, generated metadata-image restrictions, or root catch-all. Those production prerequisites were absent in the reviewed heads; next dev remains an affected developer workflow before patching. No untrusted-browser exploit was reproduced, and no attack payload was run.

Source-map-js 1.2.2 fixes high GHSA-68fv-2mgg-jv7q, affected >=1.0.0 <1.2.2. Paths include Next -> PostCSS and isomorphic-dompurify -> jsdom -> css-tree, plus dev Vitest -> Vite -> PostCSS. Exploitation requires passing an indexed source map with an enormous section offset into SourceMapConsumer. PostCSS contains consumer sinks for build inputs; css-tree's inspected path uses SourceMapGenerator. No request-controlled indexed-map consumer was identified. It is nevertheless production-installed, so it is patched rather than dismissed.

Critical GHSA-5gmw-xhrv-c9v3 (tinypool <=2.1.0, fixed 2.1.1) and GHSA-85c8-ppgw-ccpr (tinypool <2.1.2, fixed 2.1.2) remain in dev Vitest 3.2.7 -> tinypool 1.1.1. The two critical package entries are tinypool and propagated Vitest, not two independent direct application RCE paths. Both require an upstream prototype-pollution primitive in the test process and an attacker-loadable module. The first materializes inherited execArgv/env worker options; the second reads inherited filename from explicitly passed run options. This installed runner does create workers during npm test, so the CI/developer supply-chain risk is real. Production Docker installs omit these marked dev dependencies, no runtime imports were found, and no public HTTP entry point into the test pool was identified. This is not evidence that all test execution is safe or that malicious browser requests were experimentally ruled out.

Moderate GHSA-82fw-gwwq-j7x9 remains in Vitest/@vitest/mocker 3.2.7, affected >=2.1.0 <4.1.11 and fixed 4.1.11. File disclosure requires reachable public mocker/interceptor Vite HMR registration or authenticated browser-mode RPC. Here npm test uses vitest run with no browser-mode/public API/public mocker-plugin configuration. It is distinct from the prototype-pollution worker gadgets and not a demonstrated exposed-server exploit. No supported 3.x patch fixes these issues. A separately authorized migration to Vitest 4.1.11 could remove tinypool and fix mocker, but no major upgrade is authorized in this patch.

Until that migration, run tests only in disposable non-root workers with no production/API credentials, publishing/signing credentials, SSH agent, Docker socket or deployment mounts, and deny network during tests after dependency installation. Untrusted tests/dependencies already execute code; containment reduces blast radius rather than remediating the advisories.

High GHSA-vfj7-8cjw-p6xm remains in braces 3.0.3 (affected <=3.0.3, no published fix). The exact chain eslint-config-next 15.0.3 -> @next/eslint-plugin-next 15.0.3 -> fast-glob 3.3.1 -> micromatch 4.0.8 -> braces 3.0.3 yields five high package entries from one advisory. These are production-installed because lint dependencies sit in dependencies, but source review found zero app imports and zero request-controlled glob entry points. The ESLint config does not activate the Next plugin and lint uses fixed trusted paths. Deeply nested untrusted patterns can still crash tooling; do not dismiss the finding or use npm audit's proposed major downgrade as a safe fix.

Low GHSA-238p-pmpm-9mq7 remains in KaTeX 0.16.45 and propagated marked-katex-extension 5.1.8, affected >=0.11.0 <0.18.2, fixed 0.18.2. Untrusted math is reachable through private/shared notes and chats, but exploitation needs preexisting prototype pollution or attacker-influenced option prototypes plus unsanitized insertion. All reviewed rendering uses renderMarkdown and separate DOMPurify sanitization, implementing the official workaround. This mitigates the described XSS but does not prove immunity to other pollution effects. The required KaTeX minor upgrade is out of scope.

All advisory IDs above link to their official records at https://github.com/advisories/ followed by the stated ID. The framework patch recommendation is https://nextjs.org/blog/september-2026-security-release. This review is exact-lock source-based reachability assessment, not a full production penetration test. Remaining test-tool risks are explicitly accepted for this patch scope, not marked fixed. Final production build and browser verification must bind to the resulting new head; old e241fe0 or 402cf9d evidence does not attest it.
