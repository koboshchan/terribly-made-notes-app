Deployment and validation notes for this review branch

Before deploying, grant admins in the Clerk dashboard under user Metadata > Private by setting {"admin": true} (a JSON boolean, not a string). This matches cal: every server admin check reads clerkClient.users.getUser(userId) and requires privateMetadata.admin === true. Missing/false metadata and failed Clerk lookups deny access. Registration order, public metadata, session claims and existing Mongo admin flags are not trusted; no separate admin environment variable is needed.

Set PROVIDER_BASE_URL_ALLOWLIST to a comma-separated list of exact approved STT/LLM base URLs, including each /v1 suffix. Model discovery and inference fail closed for URLs outside this list, and inference follows no redirects. Only explicitly allow trusted internal services. Set NEXT_PUBLIC_APP_URL to the canonical HTTPS origin used in share links. Keep all API keys in deployment configuration or owner-managed model settings, never source control.

Back up MongoDB and the audio data directory. While old workers are stopped, run node scripts/migrate-shortcut-tokens.mjs, then node scripts/backfill-processing-jobs.mjs. The first migration replaces plaintext bearer tokens with SHA256 digests and assigns upload scopes plus a 90-day expiry. Existing saved shortcuts continue to work until expiry; secrets will no longer be returned from list responses. The second migration repairs legacy processing notes and queues jobs whose original audio still exists; missing recordings become explicit errors. Neither migration was executed in this environment.

Jobs now persist checkpoints and leases in processing_jobs. Restart recovery runs while a long-lived Node server is alive; this is not a standalone worker for scale-to-zero/serverless hosting. Replicas must share the same persistent DATA_DIR and MongoDB. Stage concurrency is per process, not a global cluster cap. parallel=false means one; parallel=true defaults to two and is capped at ten, configurable through pipeline stage concurrency or PIPELINE_AUDIONORMALIZATION_CONCURRENCY, PIPELINE_TRANSCRIPTION_CONCURRENCY, PIPELINE_SUMMARIZATION_CONCURRENCY, PIPELINE_GENERATION_CONCURRENCY. Provider deadlines default to 300000 milliseconds, MEDIA_TIMEOUT_SECONDS to 600. Provider transient retries may repeat a charge after an ambiguous failure; chat does not retry.

Upload defaults are 64 MiB per audio file (MAX_UPLOAD_BYTES, hard ceiling 256 MiB), four hours (MAX_AUDIO_SECONDS), 100 attempts per user/day, 2 GiB/day (MAX_DAILY_UPLOAD_BYTES), 10 GiB stored original audio per user (MAX_USER_STORAGE_BYTES), and five processing notes. Daily byte/count reservations are atomic. A per-user leased admission lock serializes storage/job checks. Proxy buffering uses the configured file cap plus multipart overhead. Parsing still buffers bounded uploads in memory; reverse proxy limits remain important. Storage quota counts original bytes, not generated MP3/chunk artifacts. Mounted data directories must be writable by the unprivileged node user in Docker.

Public AI chat is now an explicit share permission, disabled unless the owner opts in. Old readable shares remain readable; old shares without explicit consent cannot invoke AI. New shares expire in 1 to 365 days, default 30; owner controls revoke and rotate links. Limits are ten requests/token/minute, twenty per client/minute and PUBLIC_CHAT_DAILY_REQUESTS (default 100) per owner/day. Do not set TRUSTED_CLIENT_IP_HEADER unless an upstream trusted proxy overwrites that header and clients cannot bypass it. With no trusted header, clients share a conservative unknown-IP bucket. Existing perpetual read-only links are not silently expired.

STT capability profiles in global settings support maxBytes, chunkSeconds, overlapSeconds, format (mp3/wav), sampleRate and channels. Default chunks are five minutes, two seconds overlap, at most 20 MiB. The existing admin form does not expose every new capability or concurrency field, so configure the stored global settings deliberately where necessary. LLM_SUMMARY_MAX_TOKENS defaults to 6000; LLM_CONTEXT_CHARS defaults to 48000. Oversized summaries fail explicitly rather than silently truncating recordings. Chat retrieves bounded lexical sections with source labels, not a vector index. Upload study preferences select flashcards and quiz independently; successful materials survive retry of a failed sibling. Fully on-demand post-upload study generation is not implemented.

Validation used npm ci --ignore-scripts --legacy-peer-deps, TypeScript noEmit, 15 passing Vitest cases (sanitization plus request/token/provider/share/chat limits), focused ESLint security checks, and a complete Next production build with the app's existing public Clerk publishable key. The initial build without that key failed at Clerk prerendering, not compilation. Lint's removed next lint command was replaced with ESLint. npm audit --omit=dev reports zero vulnerabilities; two moderate dev-only Vitest/mocker advisories remain, requiring a major test-runner upgrade. Per-commit checks were mostly TypeScript, not a fresh install/build/lint every commit. No live Mongo/provider integration, worker restart simulation, browser exploit test, Docker build, or iOS build was executed.

The iOS companion branch has protected account/server cache partitions, versioned offline data, truthful offline transcripts, Keychain session handoff, file-backed background uploads, owner/server binding, coordinated record files, status polling, recoverable recording drafts, manual class upload, correction sheets, share controls, Markdown export, VoiceOver labels, and remembered extension language. Generate the Xcode project again with xcodegen. Both targets require the same expanded Keychain group entitlement and app group. Validate signing, Keychain access, Clerk token expiry, extension termination/relaunch, account changes during uploads and recording interruptions on device before merging. Swift is unbuilt on Linux.

Review item 25 remains partial on iOS. Bulk share, multi-note chat, incoming share-link routing, persistent native study/chat progress and a full extension language picker are not implemented. Web study/chat progress is account-scoped local browser state, not synchronized across devices. These gaps are documented rather than presented as completed features.
